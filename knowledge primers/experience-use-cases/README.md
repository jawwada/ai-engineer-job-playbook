# Experience Use Cases — the systems behind the resume

An interactive, single-file page that turns the four engagements on the resume — Capital Group (via TEKHQS), Noctal, Virtual Minds and Xiom.AI for RDX Sports — into ten use cases written the way an interviewer wants to hear them: the scenario and its actors, the data with example records, the solution design with the model choices of 2026, the method step by step with the human in the loop and the learning loop, what goes wrong, the code, and the sentences to say in the room. Open `experience-use-cases.html` in any browser; no build step, no network needed beyond the Google Fonts link (the page falls back to system fonts without it).

## What is on the page

Ten use-case cards, each with seven tabs — **Scenario** (actors, constraints, a diagram), **Data** (schemas and example records), **Design** (architecture and the choices), **Method** (the steps, the gates, the loop; three cards carry a data chart), **Pitfalls**, **Code**, **Say it in the room** — plus three reference cards.

## Conventions

- Figures from the resume are marked `resume`; every other number — example records, dataset sizes, prices, fees, thresholds, targets and the worked arithmetic — is marked `illustrative` and exists to make a design concrete, not to be quoted as a result.
- Regulatory descriptions (FINRA Rule 2210, the SEC Marketing Rule, fund advertising rules, the FINRA proposal on projections filed in February 2026 and pending) are paraphrased for design; counsel owns the rules.
- Model names and dates follow the papers and releases current in October 2026 (Qwen3-Omni September 2025, Qwen3-VL-Embedding/Reranker January 2026, Audiocards February 2026, Qwen3.5-Omni April 2026, Text-Prompted CLAP July 2026, Qwen3.8-Omni-Flash September 2026, OneRanker March 2026); verify versions and statuses before quoting them. Google Cloud naming is the 2026 naming (Conversational Agents for Dialogflow CX inside Customer Engagement Suite).
- Code samples are sketches in Python (LangChain, LangGraph, PyTorch, TRL, PEFT, FastAPI), SQL, openCypher and Kubernetes YAML; library paths and arguments change, the shapes are what matter.
- The three data charts use the same validated two-colour palette as the FinOps and Observability primers, one axis per panel, a legend for two series and hover titles on marks.
- No personal rate appears on the page.
- The page is a hosted Claude artifact as well; this file is the standalone copy for the repository.
