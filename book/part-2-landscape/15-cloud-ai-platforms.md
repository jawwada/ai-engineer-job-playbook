# 15. Cloud AI platforms: AWS Bedrock and AgentCore, Microsoft Foundry, Google's Gemini Enterprise Agent Platform, and the Anthropic platform

> **What you need to be able to say:** every hyperscaler now sells the same eight boxes under different names — model catalog, inference API, retrieval/knowledge, agent runtime, tool gateway, memory, guardrails and evaluation/observability. You should be able to name the box on each cloud, say what it is good at, what it costs you in complexity, and when you would pick it over the others. Interviewers at FDE and AI-engineer level ask "which would you choose for X and why", not "list the services". Names drifted again in 2025–26 — Azure AI Foundry became **Microsoft Foundry** (Ignite, November 2025) and Vertex AI became the **Gemini Enterprise Agent Platform** (Next, April 2026), with Agent Engine renamed Agent Runtime and Vertex AI Search renamed Agent Search — so say the old and the new name once, then move on to the box.

## 15.1 The shape of every platform

Strip the marketing and each platform is the same stack:

| Layer | What it does | AWS | Azure | Google Cloud | Anthropic |
|---|---|---|---|---|---|
| Model catalog | Hosted frontier and open models behind one API | Amazon Bedrock (Claude, Amazon Nova, Llama, Mistral, Cohere, DeepSeek, OpenAI gpt-oss, …) | Microsoft Foundry model catalog (OpenAI GPT family, Claude, Llama, Mistral, DeepSeek, Phi, …) | Model Garden (Gemini, Claude, Llama, Gemma, …) | Claude family via the Claude Developer Platform (also on Bedrock, the Gemini Enterprise Agent Platform and Foundry) |
| Inference API | Chat, tools, structured output, streaming, batch | Bedrock Converse / InvokeModel, Batch inference | Azure OpenAI / Foundry Models API, Batch, Model Router | Gemini API on the Agent Platform, batch prediction | Messages API, Batches API |
| Retrieval / knowledge | Managed RAG: ingest, chunk, embed, index, query | Bedrock Knowledge Bases (OpenSearch Serverless, Aurora pgvector, Neptune GraphRAG); AgentCore Managed Knowledge Base | Azure AI Search (hybrid + semantic ranker), Foundry IQ, file search | Agent Search (formerly Vertex AI Search), RAG Engine | Files API, citations, search tool |
| Agent runtime | Hosted execution of long-running agents with sessions | Bedrock AgentCore Runtime and Harness (classic Bedrock Agents closed to new customers on 30 July 2026) | Foundry Agent Service (hosted agents) | Agent Runtime (formerly Agent Engine) on the Gemini Enterprise Agent Platform | Claude Agent SDK (you host it) or Claude Managed Agents (Anthropic hosts it) |
| Tool gateway | Expose APIs/MCP servers to agents with auth | AgentCore Gateway | Foundry tools (OpenAPI, Logic Apps, MCP) | Agent Gateway / ADK tools, MCP | MCP connector |
| Memory | Short- and long-term state | AgentCore Memory | Threads + memory in Agent Service | Sessions + Agent Memory Bank | Your store; SDK sessions |
| Guardrails / policy | Content filters, PII, authorization | Bedrock Guardrails, AgentCore Policy | Azure AI Content Safety, Prompt Shields | Model Armor, safety filters, Agent Threat/Anomaly Detection | System prompts, tool permissions, hooks |
| Evaluation + observability | Judges, metrics, traces | AgentCore Evaluations, Optimization + Observability (CloudWatch, OTel) | Foundry evaluation SDK, Foundry Control Plane, Azure Monitor | Agent Evaluation, Agent Simulation, Cloud Trace | Hooks + OpenTelemetry in Claude Code / SDK |
| Training / tuning | Fine-tuning and hosting custom weights | SageMaker AI, Bedrock custom models | Foundry fine-tuning, Azure ML | Tuning and Gemini distillation, TPUs | Not offered for Claude weights |
| Data platform | Where the enterprise data sits | S3, Redshift, Glue, Athena, Neptune | Fabric, Synapse, Cosmos DB, SQL | BigQuery, Spanner, AlloyDB | — |
| Identity | Who the agent is and what it can touch | IAM, AgentCore Identity (OAuth, OBO) | Entra ID and Entra Agent ID | Cloud IAM, Agent Identity | API keys, OAuth for connectors |

Hold this table in your head and every "do you know Bedrock?" question becomes "which box are we talking about".

## 15.2 Amazon Web Services: Bedrock and AgentCore

**What Bedrock is.** Amazon Bedrock is the managed model-serving layer: a single API (`Converse` for chat, tools and streaming; `InvokeModel` for raw provider payloads) in front of a catalog of hosted models. Anthropic Claude is the workhorse for agentic and coding work; Amazon's own Nova family (text, multimodal, Nova Sonic for speech-to-speech) is the price-performance option; Llama, Mistral, Cohere and DeepSeek cover open-weight needs. Pricing is per token (on-demand), per batch job (half price), or provisioned throughput for guaranteed capacity. Cross-region inference profiles spread load across regions; prompt caching cuts the cost of repeated prefixes.

**Knowledge Bases** are Bedrock's managed RAG: point them at S3 (and connectors for SharePoint, Confluence, Salesforce, web crawl), choose chunking (fixed, semantic, hierarchical) and an embedding model, and Bedrock writes into a vector store you own — OpenSearch Serverless, Aurora PostgreSQL with pgvector, Pinecone, Redis, MongoDB Atlas — or into Amazon Neptune Analytics for GraphRAG, where entities and relations extracted from documents are stored as a graph and traversed at query time. `RetrieveAndGenerate` does the whole loop; `Retrieve` returns chunks for your own prompt. Metadata filtering, reranking (Cohere/Amazon rerankers) and query decomposition are built in.

**Guardrails** are a separate resource applied to any model call or agent: denied topics, content filters with thresholds, word filters, PII detection and masking, contextual grounding checks (does the answer follow from the retrieved context) and, in 2026, automated reasoning checks that verify answers against formal policy rules. Guardrails are what compliance teams ask about first.

**Bedrock Agents (classic)** let you declare an agent with instructions, action groups (Lambda functions or OpenAPI schemas) and knowledge bases; Bedrock runs the ReAct loop for you. They are quick to stand up and limited in control — fine for a support bot, cramped for anything with complex orchestration. AWS now calls them **Agents Classic** and has not accepted new customers since 30 July 2026: existing agents keep working in maintenance mode, with no new features and no planned end-of-life date, and AWS recommends migrating to AgentCore.

**Amazon Bedrock AgentCore** (preview July 2025, GA October 2025) is the answer to that limit: a set of framework-agnostic building blocks for agents you write yourself in Strands, LangGraph, CrewAI, the OpenAI Agents SDK, Google ADK or the Claude Agent SDK:

- **Runtime** — serverless, session-isolated execution for long-running agents (up to eight hours per session), Python, Node or containers; each session runs in its own microVM; in 2026 it gained bring-your-own file systems (Amazon S3 Files, EFS), interactive shells, stateful MCP server hosting, AG-UI support and larger session quotas.
- **Gateway** — turns APIs, Lambda functions, OpenAPI specs, existing MCP servers and other AgentCore agents into MCP tools with unified auth, rate limits and policy; includes a managed Web Search target (GA July 2026) and passes through MCP elicitation, sampling and progress notifications. Bedrock Guardrails can run at the gateway layer through AgentCore Policy (announced 17 June 2026), outside the agent's code where the model cannot reason around them.
- **Memory** — short-term event memory plus long-term memory built from configurable strategies (semantic facts, summaries, user preferences, episodic), with namespaces, metadata filters and direct ingestion of non-conversational JSON events.
- **Identity** — OAuth 2.0/JWT credential vault so agents act with user-scoped tokens instead of god-mode service accounts; on-behalf-of (OBO) token exchange arrived in April 2026, a consent portal in September 2026.
- **Browser** and **Code Interpreter** — managed, sandboxed tools for web automation and code execution (Chrome policies, custom root CAs, browser profiles for enterprise sites).
- **Policy** (GA March 2026) — fine-grained authorization over which tools an agent may call with which arguments, written in natural language or Cedar and enforced by the gateway, integrated with Guardrails.
- **Observability** — OpenTelemetry traces and metrics into CloudWatch with agent-specific trace and trajectory views, cross-account monitoring.
- **Evaluations** (GA 31 March 2026) — built-in evaluators (correctness, faithfulness, helpfulness, harmfulness, stereotyping, tool-selection and tool-parameter accuracy, goal success, context relevance, skill selection) plus managed DeepEval/AutoEval evaluators, on-demand, batch and online sampling of live traffic; **Optimization** (GA July 2026) adds recommendations for prompts and tool descriptions mined from traces, batch evaluation, A/B tests, user simulation and (preview) failure insights; **Harness** (GA July 2026) runs an agent from `CreateHarness`/`InvokeHarness` with no orchestration code, any model provider, built-in memory and export to Strands code; **AWS Agent Registry** (GA August 2026) is a governed catalog of agents, tools, skills and MCP servers; **Payments** (preview May 2026, with Coinbase and Stripe) lets agents pay for APIs and content under budgets via x402 and the Machine Payments Protocol; **Managed Knowledge Base** (GA July 2026) is a fully managed RAG pipeline queried through the gateway.

**SageMaker AI** remains the place for training, fine-tuning and hosting your own models (JumpStart, HyperPod clusters, endpoints), and for classic ML.

**Pros.** The widest enterprise surface: IAM, VPC endpoints, KMS, PrivateLink, CloudTrail audit on everything; the most complete agent infrastructure (AgentCore) that does not force a framework; Claude and Nova under one bill; mature data services (S3, Glue, Athena, Redshift, Neptune); SOC, ISO and GovCloud coverage for AgentCore since 2026. **Cons.** Service sprawl and overlapping options (Bedrock Agents vs AgentCore Runtime vs Harness, four vector stores, three ways to run a Lambda tool) — and the pruning has started: Amazon Kendra went into maintenance mode on 30 June 2026 and closed to new customers on 30 July 2026 (AWS points to Bedrock Managed Knowledge Base), Bedrock Agents (now Agents Classic) closed to new customers the same day (AWS points to AgentCore), and Amazon Q Business no longer accepts new customers (AWS points to Amazon Quick), so check a service's availability page before designing around it; model and feature availability lags by region; quotas (requests and tokens per minute, per model, per region) need raising for production; the console is slow for iteration — you live in the CLI (the AgentCore CLI went GA in March 2026) and CDK/Terraform. **Choose it when** the customer's data and identity already live in AWS, when compliance wants VPC-only traffic, or when you need the agent-infrastructure pieces (identity, gateway, memory) without owning them.

## 15.3 Microsoft Azure: Microsoft Foundry and the Agent Framework

**What Foundry is.** **Microsoft Foundry** — called Azure AI Foundry until Ignite in November 2025, and the old name is still all over documentation and job descriptions — is Microsoft's umbrella: a Foundry resource holds shared settings (connections, model deployments, keys, networking), *projects* hold your work (the older hub-based projects live on in the "Foundry (classic)" portal; Microsoft says new investment goes to Foundry projects), and the **model catalog** exposes OpenAI's GPT family (the main reason enterprises are on Azure for AI), Claude on Foundry (since November 2025), Llama, Mistral, DeepSeek, Cohere, Microsoft's Phi small models and thousands of Hugging Face models — some as serverless pay-per-token endpoints, some as managed compute you provision. **Azure OpenAI** is the specific service for OpenAI models with Azure's identity, networking and content filters; it offers pay-as-you-go, provisioned throughput units (PTUs) for guaranteed capacity, batch pricing, and a **Model Router** (GA November 2025) that picks a model per request by difficulty and cost.

**Foundry Agent Service** is the managed agent runtime: you define an agent with a model, instructions, tools and knowledge; the service keeps threads (conversation state), runs the tool loop, and exposes an endpoint. Hosted tools include file search, code interpreter, Bing grounding (web search with citations), Azure AI Search (your index), Azure Functions and Logic Apps (hundreds of SaaS connectors), OpenAPI tools and MCP servers. Multi-agent "connected agents" let one agent delegate to others; **hosted agents** (your own agent code run in a fully managed environment, public preview November 2025, GA around August 2026 together with the Agent Framework's "agent harness" runtime — verify the date) and multi-agent workflows with a visual designer followed. **Foundry IQ** (preview November 2025) is the retrieval layer that treats grounding as an iterative reasoning step over many sources rather than one lookup, alongside **Work IQ** (Microsoft 365 context) and **Fabric IQ** (data context). The **Foundry Control Plane** adds fleet-level governance and observability; **Agent 365** is the Microsoft 365-side registry and governance of agents; **Entra Agent ID** gives every agent a durable identity. Everything is governed by Entra ID, private networking and content safety.

**Azure AI Search** is the retrieval workhorse: hybrid keyword + vector search, a semantic ranker, integrated vectorization (chunk and embed on ingest), and skillsets for OCR and entity extraction. It is the most mature managed RAG index of the three clouds for document-heavy enterprise corpora.

**Microsoft Agent Framework** (open source, public preview October 2025, version 1.0 GA on 3 April 2026) merges Semantic Kernel (the plugin/DI model) and AutoGen (multi-agent patterns) into one SDK for Python and .NET: `ChatAgent` as the unit, graph-based workflows with explicit edges, MCP client and server support, A2A, OpenTelemetry tracing, and one-call hosting on Foundry Agent Service. Semantic Kernel and AutoGen remain for existing code; new work goes to the Agent Framework.

**Copilot Studio** is the low-code sibling (chapter 28): business users build conversational and autonomous agents on M365 data; engineers hand them MCP servers and Foundry models. **Microsoft Fabric** is the data platform (OneLake, lakehouse, warehouse, Power BI, Data Science workloads) and the usual home of the enterprise data Foundry agents retrieve from.

**Content safety**: Azure AI Content Safety (hate, violence, sexual, self-harm classifiers), Prompt Shields (jailbreak and indirect injection detection), groundedness detection and protected-material detection are available as API calls and as filters on Azure OpenAI deployments.

**Pros.** OpenAI models with enterprise controls; the deepest integration with corporate identity (Entra ID), Microsoft 365, Teams and Power Platform; strong content-safety tooling; Fabric for data. **Cons.** Naming churn (Azure AI Studio → Azure AI Foundry → Microsoft Foundry; Agent Service previews; "Foundry Models" vs "Azure OpenAI") confuses teams and documentation; capacity and quota management (tokens-per-minute quotas per deployment and region, PTU sizing, model availability by region) is a job in itself; many features sit in public preview for a long time. **Choose it when** the customer is a Microsoft shop (Entra ID, M365, Dynamics), when OpenAI models are mandated, or when the agent must live inside Teams and Copilot.

## 15.4 Google Cloud: the Gemini Enterprise Agent Platform (formerly Vertex AI)

**What the Agent Platform is.** The **Gemini Enterprise Agent Platform** is Google's unified ML and GenAI platform: the Gemini models (long context, native multimodality, fast "Flash" tiers and the "Pro" reasoning tier), Model Garden with Claude, Llama, Gemma and more, tuning (supervised, preference, distillation), batch prediction, and the classic ML stack (pipelines, feature store, model registry, prediction endpoints, TPUs). Until Next '26 (22 April 2026) it was called Vertex AI; Google's product pages now read "Gemini Enterprise Agent Platform (formerly Vertex AI)", the console redirects "Vertex AI" to "Agent Platform", the agent products were renamed, and the underlying API stayed `aiplatform.googleapis.com`. Expect both vocabularies in job descriptions for a year.

**Vertex AI Agent Builder → Gemini Enterprise Agent Platform.** The pieces: the **Agent Development Kit (ADK)** is the open-source, code-first framework (Python, Go, Java, TypeScript) with sequential/parallel/loop workflow agents, LLM agents, tools, callbacks, built-in evaluation and a dev UI; **Agent Runtime** (formerly Agent Engine; the documentation URLs still say `agent-engine`) is the managed runtime that deploys an ADK (or LangGraph, CrewAI, LlamaIndex) agent with autoscaling, **Sessions** for conversation state, **Agent Memory Bank** for long-term memory, example store, evaluation and tracing; **Agent Studio** is the visual builder; **Agent Garden** holds templates; the **Agent2Agent (A2A) protocol** (donated to the Linux Foundation in 2025, v1.0 in March 2026, now in the Agentic AI Foundation) lets agents on different stacks discover and talk to each other via agent cards; **Agent Identity**, **Agent Gateway**, **Agent Registry**, **Model Armor** (prompt-injection and data-loss screening) and agent threat/anomaly detection form the governance layer; **Agent Simulation**, **Agent Evaluation** and **Agent Optimizer** cover the quality loop. **Agent Search** (formerly Vertex AI Search) is the managed search/RAG product for websites and enterprise documents; **RAG Engine** is the lower-level managed corpus for custom pipelines. **Gemini Enterprise** (formerly Agentspace) is the employee-facing assistant and agent marketplace on top.

**CX Agent Studio**, part of **Gemini Enterprise for Customer Experience** (formerly the Customer Engagement Suite), is Google's current builder for contact-center agents and, in Google's words, "the evolution of Dialogflow CX". **Dialogflow CX** (branded Conversational Agents for a while) now sits under "legacy conversational agents" in Google's documentation — still documented and running, with no shutdown date announced — and remains the deterministic + generative stack most existing deployments use: flows, pages, intents, entities, playbooks, data stores, telephony. Chapters 28 and 41 cover both in depth.

**BigQuery** is the gravitational center: SQL over petabytes, BigQuery ML (train and call models in SQL, including Gemini via `ML.GENERATE_TEXT` and the newer `AI.GENERATE` family, embeddings via `ML.GENERATE_EMBEDDING`), vector search inside BigQuery, and Dataform/Dataflow for pipelines.

**Pros.** Gemini's long context and multimodality, the strongest data+AI story through BigQuery, a well-designed open framework (ADK) with a real managed runtime, and the cleanest evaluation tooling. **Cons.** Frequent product renames (Dialogflow CX → Conversational Agents → CX Agent Studio; Discovery Engine → Vertex AI Search → Agent Search; Vertex AI Agent Builder and Vertex AI → Gemini Enterprise Agent Platform), IAM and project/org hierarchy that newcomers find heavy, and a smaller enterprise-consulting ecosystem than AWS and Azure in some industries. **Choose it when** the data is in BigQuery, when multimodal or very long context matters, when you are building a contact-center or voice agent, or when the customer is Google Workspace-centric.

## 15.5 Anthropic: Claude Developer Platform, Claude Agent SDK, Claude Code and MCP

**Claude Developer Platform** is the direct API: the Messages API with tool use, structured outputs, extended thinking, prompt caching, the Batches API (50% cheaper, asynchronous), the Files API, citations, server-side tools (web search at \$10 per 1,000 searches, web fetch at no extra charge, code execution with 1,550 free container-hours a month, computer use) and the MCP connector that lets the API call remote MCP servers for you. The current models — Fable 5.1, Opus 5.5 and Sonnet 5.5 — carry a 1M-token context window billed at standard rates, Haiku 4.5 a 200k window. **Agent Skills** package instructions and scripts the model loads on demand; the format became an open standard in December 2025 and other harnesses (AgentCore, Deep Agents) load the same folders.

**Claude Agent SDK** (Python and TypeScript; formerly the Claude Code SDK) is the agent harness that powers Claude Code, exposed as a library: an agent loop with file, shell, web and MCP tools, subagents, hooks (pre/post tool), permission modes, sessions and streaming. You host it (a container, Lambda, AgentCore Runtime, Google's Agent Runtime, Fargate); it does not host for you. It is the fastest way to build a coding-style agent that operates on files and systems, and it is what you compare against LangGraph or Strands in an interview. **Claude Managed Agents** (public beta from 9 April 2026) closes the hosting gap: Anthropic runs the session in an isolated container with code execution, browsing, file tools and a credential vault for OAuth secrets, billed as tokens plus \$0.08 per active session-hour (idle time is free) — the Anthropic-side equivalent of AgentCore Harness or Foundry hosted agents.

**Claude Code** is the terminal agent built on the SDK — the tool this book's Part 1 turns into a job-search agent. **MCP (Model Context Protocol)** is the open standard (under the Linux Foundation's Agentic AI Foundation since December 2025) for connecting models to tools and data: servers expose tools, resources and prompts over stdio or streamable HTTP; clients (Claude, ChatGPT, Cursor, VS Code, Bedrock AgentCore Gateway, Foundry, ADK) discover and call them. Knowing MCP's primitives — tools, resources, prompts, OAuth 2.1 for remote servers, tasks for long-running calls — is table stakes in 2026 interviews, and so is knowing that the 2026-07-28 revision changed the shape of the protocol: no sessions or `initialize` handshake (every request carries its protocol version and capabilities in `_meta`), a `server/discover` call for capability discovery, server-initiated requests (sampling, elicitation, roots) replaced by a multi-round-trip pattern in which the server returns `input_required` and the client retries with the answers, tasks moved into an extension, Sampling, Roots and Logging deprecated, Dynamic Client Registration deprecated in favour of Client ID Metadata Documents, and OpenTelemetry trace context carried in `_meta`. Most deployed servers still speak 2025-06-18 or 2025-11-25; gateways translate.

**Pros.** The strongest agentic and coding behaviour per dollar in most team benchmarks, a full agent harness as a library, the MCP ecosystem, and availability on all three clouds under their compliance umbrellas. **Cons.** One model family; managed hosting is new (beta) and narrower than the clouds' agent stacks; costs climb without prompt caching and batching; rate limits by tier.

## 15.6 How to choose, and how to say it

1. **Follow the data and the identity provider.** Agents are only as useful as the systems they can reach; the cloud that already holds the data, the IAM roles and the audit trail wins by default.
2. **Separate the model decision from the platform decision.** Claude is on Bedrock, the Gemini Enterprise Agent Platform and Foundry; GPT is on Azure; Gemini on Google. A provider abstraction (LiteLLM, a thin internal client, or the Converse/Foundry/Gemini API) at the model boundary keeps you free to move.
3. **Buy the undifferentiated plumbing, build the differentiating loop.** Identity, gateway, memory, guardrails and observability are the same for everyone — rent them (AgentCore, Agent Runtime, Foundry Agent Service). The agent's reasoning, tools and evaluation are yours.
4. **Count the operational cost, not the token price.** Quotas, regional availability, PTUs, VPC endpoints and preview features are where projects slip; token prices differ by 20–40% between clouds, operations by 10×.
5. **For an FDE answer**, lead with the customer's constraints (data residency, SSO, approved vendors), name the box on their cloud for each layer, and state what you would still build yourself.

### Critic's additions: the operational questions the table hides

The box names are the easy half. The questions a Google, AWS or Microsoft interviewer asks next are about what happens at the edges, and the honest answers are the same on every cloud:

| Topic | What to know | Where it bites |
|---|---|---|
| Quotas | Bedrock: requests and tokens per minute per model per region, raised by ticket; cross-region inference profiles spread load. Azure OpenAI: tokens-per-minute per deployment, PTUs for guaranteed capacity, model router to spill over. Google: per-project quotas, Provisioned Throughput for reserved capacity. | Launch day; a demo that worked at 2 RPM fails at 200 |
| Capacity pricing | On-demand per token; provisioned (Bedrock model units by the hour, Azure PTUs, Google Provisioned Throughput) for steady load; batch at 50% for anything offline | Idle provisioned capacity is the most common FinOps leak (chapter 31) |
| Model lifecycle | Every catalog retires versions on roughly a 6–12-month notice; dated IDs, deprecation calendars, re-run the eval set on every swap | Silent quality drift when an alias moves |
| Data boundaries | Zero-retention and no-training terms are contractual, not defaults; cross-region inference may move data across borders unless you pin a geography (sometimes at a 10% premium) | Residency reviews |
| Network | VPC endpoints / PrivateLink / VPC Service Controls so inference and tool calls never traverse the public internet; egress allow-lists for agents | Security sign-off |
| Identity for tools | On-behalf-of token exchange (AgentCore Identity, Entra OBO, Google Agent Identity) so tools see the user's permissions, not the agent's | "How do you stop the agent reading everything?" (chapter 30) |
| Observability export | All three runtimes emit OpenTelemetry; make sure traces, token counts and cost attributes land in the backend the customer already runs | Day-2 operations |
| Preview risk | Preview features lack SLAs and can change APIs; keep a list of which boxes in your design are GA | Procurement and architecture review |

**Interview line:** *"I pick the cloud where the customer's data and identity already live, keep the model behind a thin abstraction so we can run Claude or GPT or Gemini, rent the agent plumbing — identity, gateway, memory, guardrails, traces — from AgentCore, Agent Runtime or Foundry, and own the orchestration loop and the eval set, because that is where the quality comes from."*
