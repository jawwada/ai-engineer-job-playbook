# 7. Optimizing the resume for Forward Deployed Engineer and AI Engineer roles

The same two-page document is read three times: by an ATS keyword filter, by a recruiter for about eight seconds, and by a hiring engineer for two minutes. Optimize for all three in that order.

**What the two roles actually screen for.** A *Forward Deployed Engineer* is hired to sit with a customer and turn a vague ambition into a working system inside the customer's environment — so the screen is for evidence that you have shipped LLM systems into production, in someone else's stack, under security and compliance constraints, quickly, while talking to non-engineers. Words that matter: *embedded with customers, VPC / on-prem deployment, from proof-of-concept to production, discovery, workshops, demos, executive readouts, security review, time-to-first-value, renewals*. An *AI Engineer* (also *Applied AI, GenAI, LLM Engineer*) is screened for depth: Python, LLM application architecture (RAG, agents, tool use, structured outputs), evaluation, latency and cost engineering, observability, one hyperscaler in depth, data pipelines. Numbers that matter: *eval scores, p95 latency, cost per request, documents indexed, requests per day, tickets deflected, hours saved*. Both roles in 2026 expect you to talk fluently about agents, MCP, evals and guardrails; the Knowledge tab covers the vocabulary.

**Structure of the two pages.**

1. *Header*: name, target title, city and state plus "Remote", phone, email, LinkedIn, GitHub. No photo, no address, no date of birth (US norms).
2. *Headline*: one line under 85 characters — the target title and two proof points. `AI Engineer · production RAG and agent systems on AWS · 12 yrs Python`.
3. *Profile*: exactly three bullets — scope (years, domains, scale), what you build (the stack, named), how you work (with customers, with teams). These three lines and the headline are what the tailoring changes per job.
4. *Core expertise*: four grouped lines, not a cloud of forty tags: **Agentic & LLM applications** (LangGraph, Claude/OpenAI APIs, tool use, MCP, structured outputs, guardrails) · **Retrieval & data** (RAG, hybrid search, pgvector/OpenSearch/Pinecone, knowledge graphs, Spark, SQL) · **Cloud & MLOps** (AWS Bedrock/SageMaker, Azure AI Foundry, GCP Vertex AI, Docker, Kubernetes, Terraform, CI/CD, OpenTelemetry) · **Evaluation & quality** (LLM-as-judge, Ragas/DeepEval, LangSmith/Langfuse, A/B tests). The order of terms inside each line is reordered per job so the JD's must-haves come first.
5. *Experience*: per role, one line of context (what the company does, your scope), then two to five bullets. Latest two roles get most space; anything older than ten years is one line each.
6. *Selected projects* (optional, half a column): two or three public repos or demos with a link each.
7. *Education and certifications*: one line each. Cloud certifications count for FDE roles; list the vendor's exact name.

**The bullet formula.** *Verb + what you built + stack in parentheses + measured outcome + scale.* Every bullet needs a number or a concrete artifact; if neither exists, the bullet is a duty, and duties get cut. Three rewrites from real resumes:

| Before | After |
| --- | --- |
| Worked on a chatbot using LLMs for customer support. | Built a customer-support agent (LangGraph, Claude, pgvector, FastAPI) that resolves 38% of tier-1 tickets unassisted across 120k conversations/month; median handle time 9 → 4 min. |
| Responsible for the RAG pipeline. | Designed hybrid retrieval (BM25 + embeddings, cross-encoder rerank) over 2.1M policy pages; answer faithfulness 71% → 93% on a 400-question gold set at p95 1.8 s. |
| Helped customers deploy our product. | Embedded with six enterprise customers (banking, healthcare) to take proofs-of-concept to production inside their VPCs (Bedrock, Terraform, SSO, PII redaction); first value in ≤ 3 weeks each; all six renewed. |

**Keywords the ATS looks for.** Use the exact term the posting uses, and where two spellings are common, use both once ("RAG (retrieval-augmented generation)", "LLM-as-a-judge evaluation"). The terms that recur across 2026 FDE and AI Engineer postings: LLM, GenAI, RAG, agents / agentic workflows, tool use / function calling, MCP, LangChain, LangGraph, LlamaIndex, vector database (name the one you used), embeddings, reranking, prompt engineering, evaluation / evals, fine-tuning (LoRA), guardrails, observability, OpenTelemetry, Python, FastAPI, TypeScript, Docker, Kubernetes, Terraform, CI/CD, AWS Bedrock, SageMaker, Azure OpenAI / AI Foundry, Vertex AI, Databricks, Snowflake, Spark, Kafka, Postgres, SQL, IAM, VPC, SSO, PII, HIPAA/SOC 2, customer-facing, stakeholder management, solution architecture, discovery, proof of concept. Put a term on the resume only where it is true; the skill-years table is the source.

**ATS parsing is a real constraint.** Two-column layouts, text boxes, icons and tables often parse out of order or vanish in older ATS systems (Workday, Taleo, iCIMS). Keep a single-column *ATS version* of the master resume for company career sites, and use the designed version for LinkedIn Easy Apply, Dice and email. Test once: upload the PDF to LinkedIn's or Indeed's resume import and look at what came through — if the dates and titles are scrambled, so are they in the ATS. Keep standard headings (*Experience, Education, Skills*), real text (no images of text), and a file name like `Jane Doe - Resume - Acme.pdf`.

**Tailoring per job in ten minutes** (this is what `/resume-tailor` automates): read the JD and extract the five to eight must-haves; map each to the evidence you have (bullet, project, years); rewrite the headline and the three profile bullets so the must-haves appear in your words with a number next to each; reorder the expertise lines; leave the experience bullets alone; export the PDF and check it is still two pages. The agent also writes a 150-word cover note (fit → evidence → logistics) because many ATS forms have the field and recruiters skim it.

**FDE-specific signals to add** if you have them: industries you have deployed in, deployment environments (AWS GovCloud, customer VPC, on-prem Kubernetes, air-gapped), the security reviews you passed, how long it took to reach first value, travel you are willing to do ("up to 25%"), and one line showing you can run a workshop or a demo. **AI-Engineer-specific signals**: evaluation numbers, latency and cost figures, scale, reliability work (retries, fallbacks, caching, rate limits), and anything you open-sourced.

**The checks the kit runs on every tailored resume**: still two pages; every profile bullet has a number; at least 70% of the JD's must-have terms appear, each backed by the skill-years table; no first person; dates match LinkedIn; the PDF text extracts cleanly. If a check fails, the application waits for you.

**Mistakes that get otherwise strong candidates filtered out**: a skills cloud of sixty tools; bullets without outcomes; three or more pages; an objective statement; "references available on request"; a different title on LinkedIn than on the resume; keyword stuffing in white text (ATS systems flag it and it is dishonest); and claiming tools you touched once — the technical screen finds out in five minutes.
