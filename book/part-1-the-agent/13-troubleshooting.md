# 13. Troubleshooting

These are the failures that came up while the kit was built and tested. Where a fix is built into the kit, the table says so; the table is so you recognize the symptom. Script errors come with exit codes: `tailor_resume.py` returns 0 ok, 1 usage, spec or profile error, 2 anchor not found or ambiguous (nothing written), 3 PDF longer than `resume.max_pages`, 4 PDF conversion failed, 5 unsupported numbers with `--strict-numbers`; `tracker.py` returns 0 ok, 1 refused or duplicate found, 2 error (bad input, unknown id).

| Symptom | Cause | Fix |
| --- | --- | --- |
| The kit's commands do not appear under `/` | `~/.claude/skills` was created after the session started | `/reload-skills`; for subagents in a new `~/.claude/agents` folder, restart `claude` once |
| `/chrome` says *Extension: Not detected* | Extension not installed/enabled, or Chrome has not read the new native-messaging host file | Check `chrome://extensions`, restart Chrome, then `/chrome` → **Reconnect extension**; restart both if needed |
| Browser tools return *Receiving end does not exist* or stop responding after a quiet hour | The extension's service worker went idle | `/chrome` → **Reconnect extension** |
| *No tab available* | The agent acted before a tab existed | Ask it to open a new tab and retry |
| Clicks and uploads fail while you work in another window | The agent's tab is in the background and Chrome throttles it | Keep the Chrome window visible; the skill's page scripts are written to work in hidden tabs (synchronous, no timers), but uploads still need a visible tab |
| The Easy Apply resume upload "succeeds" but the old resume is still attached | LinkedIn's file input is hidden; a click on *Upload resume* opens the OS dialog the agent cannot use | The skill exposes the hidden `input[type=file]` and uploads through it, then verifies the file name on the review step |
| The job panel does not change when the agent "opens" the next card | LinkedIn's single-page app ignored the synthetic click | The skills open each posting at its canonical `/jobs/view/<id>/` URL in a new tab instead of clicking cards in the list |
| The injected page helper disappears | The page reloaded (LinkedIn does this after a submit) | The skill injects its helper once per page load, so it re-injects after a reload; if you drive by hand, say "re-inject the helper" |
| A page script's output is blocked as *cookie / query string* content | Returned text contained `key=value&other=value` patterns | The skill returns structured JSON without URL-like strings; avoid asking it to print raw query strings |
| *Follow company* gets ticked, or a profile prompt appears after submit | LinkedIn defaults | Untick on the review step; choose *Not now* on the profile prompt (both are in the playbook) |
| LinkedIn says you have reached the application limit for today | Daily Easy Apply throttle | The agent stops on LinkedIn for the day and tells you; the remaining rows stay `tailored` and go first tomorrow. Lower `linkedin_max_per_day` |
| The application looked submitted but is not in LinkedIn's *Applied* list | A dialog step did not advance (a required field was empty, or a consent box was unticked) | Verify against the platform's own record before marking `submitted`; the skill does this for LinkedIn (the Applied list) and Dice (the *Applied* badge), and records the confirmation page for company ATS forms |
| Workday asks to create an account | By design | The agent does not start Workday applications: it marks the row `needs-check` with the link, and you apply by hand |
| A CAPTCHA or a login page appears | By design | On LinkedIn, Dice and Indeed you solve it or sign in yourself, then tell the agent to continue; on a company ATS form the agent marks the row `needs-check` and fills nothing more |
| The tailored resume runs to three pages (exit 3) | The headline or a profile bullet grew too long, the master had no slack, or the PDF converter substituted fonts | The skill shortens the longest replacement and retries twice, then marks the row `needs-check`; keep a few lines free on page two of the master, keep the headline at most 85 characters, and install the fonts the master uses so LibreOffice renders them |
| `ANCHOR NOT FOUND` or an ambiguous anchor (exit 2) | You edited the master resume in Word, so the recorded anchor text no longer matches a paragraph (or matches two) | Run `.venv/bin/python scripts/tailor_resume.py --dump profile/master-resume.docx`, copy the new paragraph texts into `resume.anchors` in `profile.yaml`, or re-run `/job-setup`. The script already ignores differences in whitespace, quotes and dashes and handles text split across Word's XML runs |
| LibreOffice conversion fails or hangs (exit 4) | LibreOffice not installed, a stale `soffice` process, or missing fonts | Install LibreOffice or set `SOFFICE_PATH` to the soffice executable; `pkill soffice` and retry; check `soffice --version`; on macOS the binary is inside `LibreOffice.app/Contents/MacOS` |
| A numbers-guard warning after tailoring | A figure in the tailored text is not in your resume or profile | Use the figure exactly as the master states it, or drop it; the skill never ships an unsupported number |
| Screening form has a question the agent cannot answer | Not in the bank | It asks you (review mode) or stops that application and marks it `needs-check` with the question (auto mode); add the answer to `answers.yaml` |
| Duplicate postings keep appearing | Several agencies repost the same client role | The scout keeps the best source and records the rest as skipped duplicates (`tracker.py dupe-check`); add a persistent agency to `exclude_companies` |
| `tracker.py` prints `REFUSED` | A duplicate id or URL on `add`, or `remove` on a row that is already submitted or later | Expected: the tracker keeps history. Use `update` instead of `add`; `remove` is meant for the `/job-setup` test row only |
| The session gets slow and the context fills up | Long job descriptions and page dumps accumulate | Run `/compact` between batches; the skills capture JDs to files instead of keeping them in the conversation |
| Remote Control shows the session offline | The `claude` process stopped, the laptop slept with the lid closed, or the network was down for more than ten minutes in server mode | Reopen the terminal and run `claude --continue --chrome --rc`; keep the machine awake (chapter 11) |
| Gmail tools are missing from `/mcp` | Connector not connected on claude.ai, or logged in with an API key | Connect Gmail in claude.ai Settings → Connectors, then `/login` with your claude.ai account |
| `/job-setup` stops with "run install.sh" | The scripts, templates or `.venv` packages are missing | Run `bash kit/install.sh` from the repository again; `pip install failed` usually means a network problem, and re-running installs only what is missing |
| The apply playbook is not used when you ask in plain words, or from `/loop` | `/job-apply` (like `/job-setup`) is user-invoked only (`disable-model-invocation: true`), so Claude cannot load it on its own | Type `/job-apply <id>` or `/job-apply queued` yourself |

If a problem is not in this table, ask the agent to explain what it saw ("take a screenshot and tell me what is on the page") before retrying; almost every stuck state is visible in the Chrome window.
